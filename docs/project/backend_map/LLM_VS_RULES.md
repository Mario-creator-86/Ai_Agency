# LLM vs strict rules: how involved is the language model in the backend?

> **The question.** How much of AMN-AI's backend is decided by language models, and how much is
> code with strict rules? Who has the last word where it matters (money, quality, publication)?
>
> **Method.** Working tree of 2026-10-12 (branch `codex/simple-pixel-studio`, HEAD `3d49e9a`).
> Three independent measures: (a) the static inventory generated by `scripts/backend_map.py`
> (`STATS.md`, `inventory.json`) plus an AST count of string constants made for this file;
> (b) a census of the 915 important decision points that the eighteen verified subsystem maps
> (`subsystems/01_…` to `18_…`) recorded, each labelled with who decides; (c) the trust level of
> each of the 37 LLM call sites (`LLM_CALL_SITES.md`). Uncertain claims were checked in the code.
> Nothing was run against the studio, a model or a provider.
>
> **Vocabulary.** *Decided by*: **LLM** (the model's answer acted on with only shape/schema
> validation), **LLM_CHECKED_BY_CODE** (the model proposes, code verifies, clamps or can refuse),
> **CODE_RULE** (deterministic rule, threshold, cap or state machine), **OWNER** (the human, via
> a card, button or setting), **CONFIG** (a config file or settings value), **EXTERNAL** (a
> provider's or vendor's answer). *Trust* of a call site's answer: FINAL, CHECKED_BY_CODE,
> ADVISORY, INFORMATIONAL (defined in `LLM_CALL_SITES.md`).

---

## 1. The direct answer

- **Narrow in the code.** 37 of 3,951 functions (0.9 %) put a question to a model. They hold
  5,012 of 120,671 function lines (4.2 %), and much of those lines is the code that checks the
  answer. 151 functions (3.8 %, 17.9 % of function lines) have any static path to a model;
  82 % of the backend's function lines cannot reach one.
- **About one decision in nine involves a model.** Of 915 important decisions mapped across the
  backend: **63.9 % CODE_RULE**, **13.9 % OWNER**, **6.6 % CONFIG**, **4.9 % EXTERNAL**, and
  **10.7 % involve a model**: 6.8 % LLM_CHECKED_BY_CODE and 3.9 % LLM. About one in 25 decisions
  acts on a model's answer with only schema validation.
- **Trust.** Of the 37 call sites, 24 are CHECKED_BY_CODE, 5 FINAL, 5 ADVISORY and
  3 INFORMATIONAL.
- **What the model does:** it *writes* (topic ideas, claims, scripts, serial episodes, visual
  bibles, shot prompts and rewrites, sound plans, publication metadata, letters, chat), it
  *judges* (stills, clips, finished films, stories, rewrites, inbox letters), it *chooses among
  options code computed* (the day's topic, the version that ships, a refused candidate, which
  matters to act on, a default vendor model), and it *diagnoses* (QC failures, scene briefs).
- **What code does:** everything about money (budgets, reservations, film ceiling, balance
  margin, step caps, prices, booking), the GPU, the run gate in front of every model call,
  purchase permission (`may_act` and the Owner's paid-media rule), hard gates (story, factual,
  lint, measured QC, publishing), caps and loop limits, state machines, retries, scheduling,
  publishing mechanics, accounting and model assignment.
- **The shape.** "The model proposes and judges; the code governs" is accurate for **money, GPU,
  scheduling, publishing mechanics and accounting**: no model answer buys anything, and every
  purchase passes the same code gates. It is **not** accurate for **quality and content**. There,
  where nothing can be measured or looked up, the model's judgement stands. In five places the
  model's answer is final. In several more it overrides a measurement, closes a film, or changes
  stored state with no check on its content. A model's "no" also decides whether *bounded*
  spending happens (re-rolls, retries, redos). Section 6 lists where the shape breaks.

### 3.3 Caveats on the census

1. **The groups chose the important decisions, not every branch.** A subsystem with many small
   rules is not fully enumerated; the census measures *which kind of authority holds the
   decisions worth mapping*, not the number of `if` statements.
2. **A few decisions are counted twice**, once by each group whose code touches them (for
   example the Director's look at refused candidates in 08 and 11, the editorial viewing in 08 and
   11, the Publisher HOLD lift in 10 and 11, the repair hold in 10 and 11). Of the 36 LLM labels,
   32 are distinct.
3. **Labels at the Owner/code border vary between groups.** Code that applies the Owner's policy
   (the kernel's refusal of an unasked step, the paid-media rule) is labelled OWNER in some groups
   and CODE_RULE in others (e.g. the unasked-step refusal is OWNER in group 05 and CODE_RULE in
   group 06). OWNER + CODE_RULE together (77.8 %) is the robust figure.
4. **LLM_CHECKED_BY_CODE covers checks of very different strength**: from a verbatim-quote test
   (`backend/app/factual/agent_pipeline.py:411-418`) to a host filter on URLs the model picked
   (`backend/app/media/model_research.py:310`).

### 6.3 Where "the model proposes and judges, the code governs" holds

- **Money.** No model answer spends. Every purchase passes `may_act` (the Owner's mode and
  paid-media rule, a plan hash bound to the Owner's yes), the budget reservation, the film
  ceiling, the balance margin, the step cap and the purchase lease. The models' maximum lever is
  to *trigger* a purchase inside those bounds.
- **GPU and vendors.** The RunPod package has no model input at all (subsystem 12); vendor
  refusals are classified by code (`backend/app/media/production_policy.py:2257`).
- **Publishing mechanics.** Channel, visibility, the 7-check gate, upload and reconciliation are
  code and the Owner's policy; the model contributes metadata (re-checked) and verdicts that can
  only withhold.
- **Facts that can be looked up.** A cited claim must be SUPPORTED; a SUPPORTED verdict needs a
  verbatim quote in the source; an episode can cite only events of its day; a topic choice must
  be on the shortlist; a candidate must have been shown.
- **The hard gates of the specification.** `docs/architecture/00_MASTER_PROMPT.md` §43 (lines
  1170-1195) requires the factual, rights, platform, budget, credential and STOP gates to be
  independent of the Director, who "cannot convert a failed hard gate into PASS through prose".
  The code refuses her ACCEPT over rights, factual, content-source and production-path findings
  (`backend/app/media/director_qc.py:151-158`, `:196`; `backend/app/runbook/stages.py:4467-4477`).

### 6.4 Where it does not hold

1. **Quality acceptance is largely the model's.** The picture verdict on the finished film is
   FINAL (`picture_qc.py:904`). At the stills gate a "yes" on text, plan, scene, look and bible is
   taken as given (`backend/app/media/still_gate.py:927-957`). The Director's ACCEPT can pass any
   measured failure that is not on the not-yours list: loudness, captions, resolution, duration,
   motion floor, pictures (`backend/app/agents/reviews.py:672-707`;
   `director_qc.py:1678`). When no repair is possible her prompt steers her to ACCEPT
   (`reviews.py:1009-1022`). These technical checks are not among the §43 hard gates, so this is
   consistent with the specification, but it means a model decides whether a measured defect
   ships.
2. **The model overrides measurements.** Her look at gate-refused candidates approves a take
   without re-checking the flat band, sharpness, YuNet faces or the motion floor
   (`director_qc.py:2069-2161`), and paid motion follows.
3. **The model decides whether bounded spending happens.** A vision "no" buys re-rolls (≤2) or a
   clip retry (≤1) or sends a scene back for a new still; a REPAIR buys redos (≤5 per scene, ≤20
   per film); a rewrite review's TREATS lifts a held scene and restarts its paid-attempt count
   (`backend/app/media/assembler.py:8786-8796`). Under the Owner's live settings recorded in
   `LLM_ROUTING.md` §5 (PRODUCTION, AUTONOMOUS_CEO, paid-media rule OVER_USD 5.0), steps whose cap
   is at most 5 USD are bought without asking, so these model-triggered re-buys proceed unasked
   within the film ceiling and the daily budget.
4. **The model changes stored state with no content check.** A Director inbox decision lifts a
   Publisher HOLD (`backend/app/agents/director.py:451-465`); a mail `done` flag closes HANDOFFs
   (`backend/app/agents/mail.py:284`); an editorial REJECT closes a finished film
   (`backend/app/agents/editorial.py:518-521`); the serial's canon is the writer's declaration
   (`backend/app/story/services.py:614`); lessons and the weekly topic direction become prompt
   rules and STRATEGY memory read by later prompts (`director_qc.py:1609`;
   `backend/app/media/prompt_agent.py:3050`; `backend/app/runbook/weekly.py:440`); an UNCERTAIN
   claim verdict is recorded unchecked (`agent_pipeline.py:419-420`).
5. **The model sets vendor choice.** The steward's scores are written as given and order
   `rank_candidates` (`production_policy.py:369-378`); where the Owner left
   `allow_production_override` on, the recommendation becomes the default model, and on RunPod
   that default films every scene unasked by quality (`production_policy.py:2839-2861`). A judged
   model with no price wipes its stored price (`model_research.py:375-395`;
   `backend/app/integrations/lifecycle.py:132`).
6. **Code loosens the model once, on purpose.** A second taste-only REVISE of a script is
   overridden to PASS (`story_review.py:456-458`), so the writers' room cannot loop on taste.
7. **Model-token loops are bounded only by the token ceiling and the USD budget** in a few
   places: `describe_serial_shots` re-asks with no day cap
   (`backend/app/media/serial_storyboard.py:375`), `repair_story` has no attempt ceiling
   (`backend/app/media/sheet_story_repair.py:176`); a script may take up to 20 exchanges of 1-3
   writer runs plus a review (`stages.py:211`) and then up to `editorial_rounds` (10) judged
   versions (`backend/app/config.py:434`). The ceiling's default is 0 = none
   (`config.py:419`), and `LLM_ROUTING.md` §5 records it unset in the live studio.

**The precise shape, then:** in money, GPU, publishing mechanics, scheduling and accounting, the
model proposes and the code governs. In content and quality, the model writes and judges; code
verifies what can be measured or looked up, and the model's judgement stands where nothing can be.
That includes five FINAL answers and the overrides above, and inside the caps the model's verdicts
decide how much is spent.

## 9. Method and limits

- **Static analysis** resolves calls by name; dynamic paths are listed by hand in
  `LLM_CALL_SITES.md` §5. Reach is approximate in both directions (§2).
- **The census** covers 915 decisions chosen by eighteen groups as the important ones, each
  verified against the code and corrected (verdict FIXED). Duplicates and label drift at the
  Owner/code border are described in §3.3; the conclusions above hold under either reading
  (the model share stays near 11 %, and OWNER + CODE_RULE near 78 %).
- **Trust** follows `LLM_CALL_SITES.md`, which reconciles the different tallies in
  `LLM_ROUTING.md` §9.2 and `DECISION_AUTHORITY.md` §12 (its §6).
- **Line numbers** refer to the backend as of commit `b00083c` (identical at `3d49e9a`). Four
  later commits (`68fa0b4`, `a50407e`, `5fc7468`, `20abffd`) moved lines in eleven backend files
  and added `backend/app/media/second_look.py` with a 38th call site (`README.md` §8). Read a
  cited line with `git show b00083c:<path>`, or re-run `scripts/backend_map.py` and re-check it
  before relying on it.
