# Public Community, Moderation and Privacy

## Scope

Future fan-facing product only. Do not implement full community before core studio works.

## Public projection

Only sanitized events/fields are exposed.

No:
- API keys;
- raw prompts;
- security incidents details;
- private Owner instructions;
- internal stack traces.

## User input

Potential:
- votes;
- comments;
- idea pitches;
- display names.

All are untrusted input.

## Controls

- authentication/session;
- rate limiting;
- spam/bot controls;
- moderation;
- reporting;
- abuse handling;
- content policy;
- audit.

## Paid pitches

Payment does not buy editorial approval.

Need:
- price/terms;
- moderation;
- refund policy decision;
- receipt/transaction;
- jurisdiction/accounting review when implemented.

## Privacy

If collecting user data:
- minimize;
- define purpose;
- retention;
- deletion/export processes where applicable;
- consent/cookie decisions for analytics.

## Vote integrity

Avoid one user/bot dominating votes.

Define:
- eligibility;
- one vote/multiple;
- close time;
- tie resolution;
- whether result is binding or advisory.

## Safety boundary

Fan input cannot bypass Director/Owner factual, rights or platform rules.


## V4 Telegram / social community

Telegram, Facebook, Instagram, TikTok and YouTube community inputs are untrusted.

Community Manager must:
- sanitize;
- moderate;
- classify;
- limit prompt context;
- escalate threats/legal/security concerns.

Public marketing must not expose:
- precise internal financial accounts;
- security weaknesses;
- private staff/model credentials;
- raw legal review;
- Owner-private instructions.

Public persona pages should identify characters as AI/fictitious studio personas where appropriate.
